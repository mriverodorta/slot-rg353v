# RG353V development and release rules

- The authoritative frontend is pinned Slot plus `ports/rg353v/layer/`; the older bring-up prototype is archived under ignored `resources/bringup-prototype/`. Never export it over the current layer.
- Keep caches, prepared sources, experimental recipes, old images and evidence under ignored `resources/`. Existing ignored root compatibility links preserve historical paths. Preserve ROCKNIX source/download/build caches, Docker volumes, F-recovery backups, persistent-RAM/watchdog tools and qualification evidence.
- `localdev/provisioning/` contains personal Wi-Fi configuration and the client public SSH key plus a development server identity. It and `localdev/images/` are ignored and private. Never embed a client private key or publish a PRIVATE image.
- Use `scripts/build-localdev.sh` for the owner's development image and `scripts/build-release.sh` for public candidates. Public artifacts go under ignored `release/`; never overwrite a path while the user is flashing it. Retain the current image plus three previous versions with validation records.
- Canonical private content is `.private-rg353v/content/`, physically `resources/.private-rg353v/content/`. It includes Games, Saves, States, BIOS, Labels, Wallpapers, Screenshots and a settings snapshot. Keep one library and its version history; do not copy personal provisioning libraries into experiments.
- Run `python3 scripts/rg353v-personal-library.py pull` on the ejected shelf before and after device tests. Preserve pending local restore protection and changed-save history. Verify SSH host identity after fresh installation; never disable host-key checks.
- Library push is SD-only by default. eMMC writes require explicit owner authorization and exact serial/mount checks. Do not restore stale saves over current progress or delete content during provisioning.
- Keep automated checks silent and isolate save/state output. Do not launch games or trigger UI sounds for storage-only tasks.
- `wiki/` is the version-controlled user guide. Update module catalog, menu gating, docs and tests together. No public upload until clean-install qualification and source/license checks. The owner explicitly directed retaining Perfect artwork with creator ownership/copyright and no-license-specified notices (see CREDITS.md); do not claim that attribution establishes permission or that GPL covers this artwork.
